# NetMask v2.3.1

This release makes connection tools more reliable when Wi-Fi changes, reduces unnecessary work while scrolling, and verifies native installers before publication. Fieldnotes and the Orbit identity remain the app's design.

## Fixes

- Clear stale latency, transfer, speed-test, and sign-in results when the SSID, access point, or adapter changes. Pending requests cannot attach results from an earlier connection.
- Reload open DNS, identity, roaming, and details dialogs after a connection change and discard their older requests.
- Show missing transfer readings as unavailable. Reset gateway, jitter, and transfer baselines when the active connection changes.
- Measure Automatic DNS only when DHCP is active, show a custom current resolver separately, and verify the active configuration before applying a choice.
- Correct Windows profile/recovery mapping and explicitly select the adapter for supported MAC randomization.
- Respect the current macOS network location, reject ambiguous service labels, and confirm the reported SSID after reconnecting.
- Allow display-name masking to retry after a confirmed unchanged name, while retaining recovery records when the outcome is uncertain. Corrupt preferences disable automatic masking and silent elevation in the fallback state.
- Prevent late updater initialization from overriding newer events. Permit retry after an installer disappears, changes, or fails to launch.
- Let reassigned modified Enter reach its shortcut and avoid submitting names during IME composition.
- Embed one application manifest in Windows desktop and test hosts, fixing a GNU manifest collision and Common Controls startup failure.

## Smoother lists

Unchanged snapshots preserve list objects, rows and filtering are memoized, and selection updates affect the relevant rows. Network lists have bounded scrolling, and popover positioning is coalesced through animation frames.

In a recorded synthetic 1,000-network comparison on one Windows machine, these renderer changes used about **89% less script time** and reduced the 95th-percentile frame interval by about **80%**. The [method and raw evidence](https://github.com/billighost/netmask/blob/v2.3.1/BENCHMARKS.md) describe the workload and limitations; these are not universal frame-rate, memory, or battery claims.

## Release verification

The merge helper rejects missing, skipped, pending, failed, or stale required checks. An always-running CI gate verifies the frontend and native results. A platform cancelled before receiving a runner may remain unavailable only when GitHub explicitly confirms an allocation failure. Actual code/test failures block publication.

CI tests the complete Rust workspace and builds installers before tagging. The release workflow also checks the browser interface, publishes complete package sets for the available platforms, and generates checksums and an availability record. Missing runners are retried automatically up to three workflow attempts; a successful retry adds the platform without changing the source tag. All four platforms supply six native installers.

The earlier v2.3.0 publication was interrupted by GitHub's inability to allocate Mac runners. Its successful Windows and Linux jobs were preserved while the missing jobs were retried against the unchanged tag.

## Platform limits

Names are local labels; the router keeps broadcasting its existing Wi-Fi name. Display-name and BSSID masking change the displayed information and do not make a connection anonymous. macOS may require Location Services or Keychain permission. Linux requires NetworkManager and a compatible desktop. MAC randomization, NetBIOS, and adapter tuning are Windows features where supported.

Automated fixtures avoid changing a live network. Permission prompts, hardware reconnects, DNS and driver changes, installation, and update launches still need manual validation on target devices. Packages do not claim verified Windows publisher signing or macOS notarization.
