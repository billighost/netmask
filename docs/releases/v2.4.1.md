# NetMask v2.4.1

This reliability release makes Windows updates preserve network aliases, repairs partially changed local names, and improves installer completion and error reporting.

## Safer Windows updates

- Update NetMask in place without running the uninstall recovery path or restoring saved aliases first.
- Show a dedicated passive update progress interface and relaunch NetMask after the update finishes.
- Keep aliases, settings, and shortcuts during automatic and manually launched upgrades.
- Make the manual maintenance choice default to **Update in place**, while clearly explaining that uninstalling restores aliases.
- Mark MSI replacement as an upgrade so migration does not trigger uninstall cleanup.

## Network-name repair

- Detect Windows cases where the Network List label and saved Wi-Fi profile no longer match after an interrupted install, update, or removal.
- Keep those partial states visible and offer **Restore original** as a repair action.
- Reconcile an orphaned saved Wi-Fi profile with an old recovery record only when the SSID and recovery identity form one unambiguous match.
- Refuse ambiguous recovery guesses and preserve every recovery record for manual resolution.
- Rename the remaining saved Wi-Fi profile when Windows has already removed its older Network List entry.

## Clearer failures and installer finish

- Detect duplicate saved Wi-Fi profile labels before requesting administrator permission.
- Replace the generic administrator-operation failure with specific guidance for duplicate labels, invalid names, permission denial, and profiles that changed during the operation.
- Coalesce duplicate notifications so one failure is shown once.
- Launch NetMask asynchronously from the final setup page, preventing the installer from briefly hanging or appearing unresponsive.
- Give fresh installs and updates distinct completion wording, and hide fresh-install shortcut choices during an update.

## Verification and limits

Automated checks cover frontend behavior, small-window and dialog UX, update preservation, recovery-state matching, error classification, native platform parsing, process deadlines, and Windows NSIS/MSI compilation. Multi-platform CI separately compiles and tests Windows x64, Apple silicon, Intel macOS, and Linux x64 packages.

Recovery records are never attached to a saved profile when more than one match is possible. Those rare existing records remain preserved for manual resolution. The automated suite does not approve a real UAC prompt, rename a live network, reconnect Wi-Fi, notarize a macOS package, or prove every desktop environment's displayed name. Packages do not claim Windows publisher signing or macOS notarization.
