# NetMask v2.3.3

This release makes local network naming honest and verifiable, and moves computer-specific identity controls out of network actions.

## Confirmed local labels

- Describe renamed values as local labels used by the operating system and NetMask. Renaming does not change the Wi-Fi SSID broadcast by the router.
- Verify the refreshed saved-network row after every rename or restore before showing success.
- For the active network, also require the refreshed connection label to match. If the operating system reports success but returns the old value, NetMask reports that the change was not confirmed and keeps the recovery record.
- Cover false-success rename and restore responses in state tests and browser interaction tests.

## Device and adapter controls

- Remove device identity from per-network context menus and the main network tools panel.
- Keep the controls in Settings as **This device and adapter**.
- Explain that the hostname, hardware address, adapter, randomization, and NetBIOS values belong to this computer and its active adapter, not to the selected network or router.

## Verification and limits

Automated fixtures exercise Windows, macOS, and Linux application paths without changing a live network. Each published platform must pass its native workspace checks, tests, browser verification, and installer build in release CI.

Local-label behavior differs by operating system: Windows uses a Windows network label or saved Wi-Fi profile name, macOS uses a network service name, and Linux uses a NetworkManager connection name. None of these operations rename the router's broadcast SSID. Permission prompts and live Wi-Fi behavior still depend on the target operating system, hardware, account policy, and driver.

Packages do not claim Windows publisher signing or macOS notarization.
