# NetMask v2.8.0

Keep connection readings close with Mini mode, and repair Windows nicknames when the saved Wi-Fi profile and local network label drift apart.

Addresses the nickname report in [issue #27](https://github.com/billighost/netmask/issues/27).

## Mini mode

- Open **Mini mode** beside Overview and Journal. The small window starts at the top right, stays on top, and can be dragged to a comfortable position.
- Choose **Fieldnote**, **Ribbon**, **Soft glass**, **Little dial**, or **Signal desk** in Settings. Every design also has a tiny mode showing Wi-Fi link speed.
- Right-click the widget for custom opacity and size sliders, reading choices, and a return to full NetMask. **Customize** opens the full app directly at the mini-mode settings.
- Keep live download, live upload, Wi-Fi link rate, signal, and latency separate. Unavailable readings stay unavailable; link speed describes the Wi-Fi connection to the router, not internet capacity.
- The **NEW** button and announcement introduce the mode. Closing the announcement dismisses it permanently; the mode remains available from the navigation.

## Windows nickname repair

- Resolve saved Wi-Fi profiles through the persisted adapter/SSID identity even when Windows removes adapter associations from historical network records.
- Keep one visible representation of the same saved profile. Preserve distinct profiles instead of combining networks merely because names or SSIDs resemble each other.
- Omit obsolete disconnected Windows entries only when they have no adapter, saved-profile match, or recovery association. Mini and background active readings use connected Windows metadata while the full saved-network list keeps its complete inventory.
- Remember successful user labels and check them on connection, including while the app is in the tray. Synchronize a recreated original profile with the nickname where Windows permits the change; automatic checks never open an administrator prompt.
- Remove a recreated original profile only after confirming the same adapter/SSID, complete saved settings, and accessible credentials. Preserve managed, enterprise, inaccessible, and differently configured profiles.
- Preserve original-label recovery, sharing-mode restoration, case-only names, later renames, and rollback when a multi-step repair fails.

## Verification and limits

Automated fixtures use fictional network data and isolated storage. Native window placement, always-on-top layering, transparency, Wi-Fi readings, and permissions depend on the operating system and desktop environment; some Linux compositors can restrict layering or transparency. Router broadcasts remain unchanged.

A live Windows repair confirmed the saved nickname profile, absence of its original-name profile, unchanged original-label recovery, and a successful HTTPS connectivity check. The release PR and CI record the final automated checks and installer builds.

Both Windows installers built locally. Twelve checks of the packaged app verified all five full and tiny styles, actual Wi-Fi link readings and speed events, frameless/topmost placement, native dragging, saved controls, and restoration into Settings. A physical size-slider gesture selected and saved 120%. The test used isolated data and preserved the existing app.

Mini mode keeps a visible webview for its readings. Earlier tray-memory measurements apply to their named versions and states; this release makes no new RAM, CPU, battery, publisher-signing, or notarization claim.
